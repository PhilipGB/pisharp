## Priorities

1. **Coding tools (major behavior covered; residuals tracked):** `read`, `bash`, `edit`, `write`, `grep`, `find`, and `ls` have broad local behavior evidence and representative agent turns. The remaining source differences and unmeasured filesystem cases are recorded for the final audit.
   - `read`: small and streamed text paths decode UTF-8 consistently, preserve BOMs, and avoid UTF-16 BOM auto-detection. Image processing decodes and validates, converts BMP to PNG, and uses 2000×2000 / 4.5 MiB base64 defaults. The selected model's optional `inputLimits.images.resize` profile now flows from configured or discovered metadata into the read tool, including its provider-boundary payload limit. Local Responses and Chat Completions tool turns cover pass-through and high-entropy images plus session reload. Still open: EXIF orientation, Lanczos3 equivalence, files over 20 MiB, animated-image transformations, exact metadata/errors, broader filesystem/cancellation cases, and pinned image request/result differentials.
   - `bash`: model-tool live text updates coalesce at 100ms; direct RPC Bash forwards each decoded output chunk immediately. Shell selection honors validated `shellPath`; combined stdout/stderr, inherited process environment, UTF-8 final flush, bounded tail/full spill, cwd and finite timeout validation, 100ms rearmed post-exit drain, and process-group timeout/abort cleanup have local unit, process, agent and JSON event evidence. Model-invoked Bash receives current `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, and `PI_REASONING_LEVEL` through MAF per-run context, and Bash strips inherited stale values before starting a shell. Direct/session Bash strips Pi ANSI CSI/OSC, removes unsafe C0 and U+FFF9–U+FFFB characters and carriage returns, and replaces invalid UTF-8; interactive streamed output uses the same filter while provider context retains raw model-tool output. Direct RPC `bash` and `abort_bash` use the shared runner, stream correlated lifecycle updates, return structured output/exit/cancel/truncation data, and retain full logs. Extensions admitted through the existing personal, project-trust, or explicit-path rules can register `user_bash` handlers to claim or decline direct RPC commands, stream correlated updates, and return structured results; handler errors emit `extension_error` and fall through to later handlers or the shell. Direct Bash executions persist as `bash_execution` entries; `excludeFromContext` is retained across save/restore and controls whether a synthetic user message is projected into provider context. Deferred executions are added to agent history after an active turn, counted for history consistency, and included in compaction and HTML export. Tests cover direct chunk forwarding, normalization across split escape sequences, invalid UTF-8 replacement, sanitized spill files, raw model-tool context, default and excluded direct context, restored follow-up prompts, malformed inactive entries, compaction retention, model Bash session environment, stale-environment removal, Unix SIGKILL/SIGTERM exit-code and partial-output results, truncated timeout and abort status with readable full-log paths, handler replacement/decline/error/cancellation, and an actual CLI RPC process with explicit extension loading. `abort_bash` cancels both direct RPC commands and model-invoked Bash tools. Git inventory uses NUL-delimited `git ls-files -z`, preserving filenames with embedded newlines. Nested Git repositories are inventoried separately, so `.gitignore` rules stop at each repository boundary; ancestor `.ignore` and tool-specific ignore files continue to apply. Ignore matching supports brace alternatives and character classes alongside wildcard, anchoring, directory and negation patterns, and trims unescaped trailing spaces while retaining escaped trailing spaces. ## Working decisions

- Agent execution and tools share one Microsoft Agent Framework runtime across interactive, print, JSON, RPC and SDK surfaces. Do not move permanent product orchestration into `Program.cs`.
- Preserve canonical raw history and durable tool outcomes. Never replay uncertain side effects or claim verification from code presence alone.
- Core loop, recovery and compaction already have substantial deterministic evidence. Revisit remaining core edge cases when a new capability exposes a defect, a pinned differential requires it, or final audit shows a material gap; do not spend the next stretch on narrower compaction cases.
- After each meaningful slice: add deterministic tests, update parity evidence and this file, run focused validation, run broader validation as appropriate, commit and push, then continue to the next unresolved capability.
