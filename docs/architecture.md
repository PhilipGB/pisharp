# Architecture

Current behavioral and visual oracle: `earendil-works/pi@f1b2e77f5b13b2a199b1052cb79c235451afe7d7`, fetched 2026-10-09. The normal coding-agent product, including package-resource CLI flows and interactive visual effects, is in scope. Pure package APIs and experimental alternate runtimes unreachable from its normal executable are excluded. Overall parity remains incomplete; `parity/execution-ledger.json` records scoped evidence and remaining work.

`PiSharp.Core` contains deterministic conversation-tree, edit/diff and read-planning logic. It has no provider SDK, terminal, filesystem or process dependencies.

`PiSharp.Runtime` owns the shared agent and session behavior. `PiAgent` uses Microsoft Agent Framework `ChatClientAgent`, its function invocation and `AgentSession`. `ConversationRun` projects the selected branch into disposable MAF sessions, routes streaming lifecycle events and appends results to canonical application history. `ConversationSession` retains branch-local state and metadata. `ConversationStore` persists the native document; `PiJsonlSessionFileStore` and interchange components support Pi JSONL. Stores use atomic writes, process leases and stale-write checks. MAF internal snapshots are not the persistent interchange format.

Runtime capabilities are grouped under sessions, tools, extensions, providers, resources, MCP and Codemode. The tool registry controls exposure. `ToolLoadout` owns session selections, pending restored tools and transcript declaration order; `ToolDeclarationTranscript` retains interface revisions separately from executable functions and projects them at the shared provider boundary; `ConversationToolState` restores and persists branch-local tools/store without adding behavior to the CLI. Nested tools reuse the same execution path. MCP uses the official C# SDK for protocol, discovery, PKCE and OAuth. `McpTokenCache` adds Pi's normalized server-name/resource identity, first-reader legacy migration and private cross-process persistence/refresh coordination. Codemode executes JavaScript in a separate Node process with bounded QuickJS/WASM and host-owned tool/model callbacks. Extensions use the .NET registration API, with context transforms applied at each provider request without changing canonical history.

`PiSharp.Cli` composes runtime capabilities with provider adapters, configuration, CLI handling, interactive terminal components and JSON/RPC front ends. All modes use `ConversationRun`; protocol projectors translate runtime state and events instead of owning another agent loop. Provider clients implement compatible chat, Responses, Messages, Bedrock, Google and routing boundaries. Anthropic uses the official beta IChatClient beneath the MAF tool loop; its transcript adapter preserves initial tool declarations and inserts later inline changes at valid call/result boundaries. SystemMessageTranscript owns Pi system metadata projection; StoredToolResultReplay restores persisted MEAI result representations. Terminal rendering, keybindings, selectors, clipboard and images belong to the CLI layer. TerminalStartupPresentation builds the theme-aware startup header and project trust notice; Program composes it and TerminalScreenCompositor pins it above the transcript. Startup model-scope and loaded-resource details remain open. TerminalProviderLogin owns the authentication menus and originating-menu cancellation; TerminalProviderOAuthInteraction adapts existing OAuth methods to the terminal. RadiusMcpSetup owns the global provider-auth proposal/write, while the terminal flow invokes the existing runtime reload. `Program.cs` remains a concentration risk; touched cohesive behavior should move into feature components rather than grow there.

`PiSharp.Tests` combines deterministic Core/runtime tests, provider HTTP/SSE fixtures, MCP child processes, CLI/RPC processes and Linux PTY checks. `tools/parity` contains reproducible current-Pi comparisons, with normalized evidence in `docs/parity/fixtures`. Tests need no live provider credentials. Existing local/CI checks prove their covered slices, not full visual or behavioral parity. A reusable full terminal cell/style/cursor/mode differential harness is the next blocking enabling milestone; official MCP conformance remains required. First-class llama.cpp router login/configuration, model management/projection and Hugging Face download form the next near-term provider family, with configuration shared by chat and native classifiers.

Session recovery checkpoints prompts, tool intentions/outcomes and assistant history, and does not replay unknown tool side effects. Network-filesystem locking, native platform coverage, complete provider wire parity and current-Pi TUI interactions remain explicit audit work. Project trust gates resource loading; it is separate from process isolation. `ConversationRun`, `ConversationSession` and `PiJsonlSessionInterchange` also remain concentration risks that require feature-local extraction when touched.
