# PiSharp parity matrix

This matrix tracks observable compatibility with Pi `main` at revision
`d7296c063b7971a7298769cfff1a167a9a16f8ed`. It is deliberately separate from
feature marketing in `README.md`: a capability is not considered complete until
its behaviour has a conformance test or an explicit intentional-difference note.

Status values:

- **Exact** — the public shape and observable behaviour are intended to match.
- **Equivalent** — the implementation differs internally but has the same user-facing contract.
- **Partial** — the main path exists, but important behaviour or protocol details are missing.
- **Missing** — not implemented.
- **Intentional difference** — deliberately outside the current .NET product boundary.

Pi paths below are relative to `/tmp/pi-reference` in the development
checkout. The reference fixture inputs in `tests/PiSharp.Core.Tests/Fixtures/pi-v3`
are copied/reduced from the pinned source contracts and are not generated by
PiSharp.

## Phase 0 conformance fixtures

Fixtures are intentionally small, deterministic contract samples:

- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/pi-session.jsonl` — Pi v3 header and typed message entries.
- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/json-events.jsonl` — lifecycle, message delta, tool, retry, and compaction event shapes.
- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/rpc-requests.jsonl` — representative current RPC commands.
- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/tool-schemas.json` — Pi's normal coding-tool names and schema anchors.
- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/prompt-template.md` — placeholder expansion contract.
- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/skill/SKILL.md` — skill frontmatter contract.
- `tests/PiSharp.Core.Tests/Fixtures/pi-v3/package.json` — `pi` package manifest contract.

The fixtures are compatibility inputs, not claims that the current implementation
already consumes every shape. Phase 1 and Phase 8 will turn them into executable
golden comparisons as the corresponding application-owned models are introduced.

## Update rule

When upstream Pi changes, update the pinned revision, add or revise the relevant
fixture, change the matrix status, and add a conformance test before changing
runtime behaviour. Intentional .NET differences must name the affected capability
and remain explicit here.
