# Current-Pi terminal system-theme baseline

Current Pi `main` was checked on 2026-09-28 at `e1787702d32e0a7fd7387840c918faa4d1286187`. The relevant implementation is `packages/coding-agent/src/modes/interactive/theme/{theme-controller.ts,system-theme.ts,theme.ts,theme-json.ts}` and `packages/tui/src/terminal-colors.ts`.

With no explicit theme setting, Pi uses a generated `system` theme. It queries foreground/background with OSC 10/11, palette entries 0–15 with OSC 4, and device attributes with DA1 in one coordinated request. The bounded query resolves when DA1 arrives or after its timeout; partial replies are retained and late replies are consumed through DA1. The generated palette uses reported terminal colors and palette hues when available, falls back to indexed palette colors where needed, and maintains at least 4.5:1 contrast for body text against the background and supported panels.

Appearance detection prefers terminal background, then a reported light/dark scheme, then `COLORFGBG`, then dark. OSC mode 2031 change reports trigger another color query and active-theme refresh. System-theme tests cover readability, contrast ordering, terminal foreground/palette influence, grayscale, no-background fallback, and the absence of explicit export colors. Theme-controller tests cover partial and late replies, appearance re-query, system-theme fallback, and avoiding redundant rerenders. Terminal-color tests cover OSC 10/11/4 parsing, one-write batching, DA1 completion, and late reply consumption. Theme parsing accepts OKHSL and OKLCH.

PiSharp implements the coordinated query in `TerminalColorQueryController`, report handling in `TerminalColorResponse`, and generated colors in `TerminalSystemTheme`. `TerminalScreen` follows appearance reports and re-renders retained theme-dependent content. `TerminalThemeTests` covers Pi-pinned dark/light/background-only color vectors and the 4.5:1 body-text invariant; `TerminalPtyTests.TerminalColorQueriesWorkThroughLinuxPty` covers the terminal query stream.
