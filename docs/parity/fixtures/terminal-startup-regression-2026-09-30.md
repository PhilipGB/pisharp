# Interactive terminal startup regression — 2026-09-30

Fetched and verified `origin/main` before changes: `72633674f53a43c60aef67c2077d5cf3132b1e52`, exact-head Linux CI [36642628468](https://github.com/PhilipGB/pisharp/actions/runs/36642628468) was green. This runtime regression was not covered by that green suite. Upstream parity remains pinned to `1b347794e2a630e4359f2584f4eea388145d0ddf`; no additional parity implementation is included.

Root cause: TerminalInput used the same empty event for stdin EOF and consumed OSC/DA1/appearance/unknown CSI traffic. The idle editor and modal list interpreted that event as EOF. The existing colour-query PTY test could pass after early exit because it did not require another interactive command.

Fail-first evidence: four blocking-read and four polled-read cases failed on the old parser; the strengthened Linux PTY test failed because process exit won the race against the post-first-OSC editor-render marker. The test disables script's input echo, waits for emitted queries and the idle footer, sends one OSC reply plus an editor probe, sends remaining background/palette/DA replies, requires the real `/session` response, then exits with `/quit`.

Input contract: actual EOF is explicit through TerminalInputEvent.IsEndOfStream. Blocking Read skips control traffic until user input or real EOF. TryRead parses controls while input is available and returns without waiting for another user event. Idle editor, active-run handler and modal list use explicit EOF. Truncated controls remain discarded; validated colour callbacks, malformed/oversized OSC protection and paste limits remain. Native stdin hangup is readable EOF; interrupted reads retry and read errors do not masquerade as EOF.

Late replies did require bounded completion. A separate Linux PTY reproduction sent `/quit` immediately before the outstanding reply burst; all OSC/DA bytes remained on the parent tty after process exit. Query/input completion now disables appearance following and consumes controls through the existing DA fence for at most 100 ms. It stops at genuine input and retains the original bytes (including keys, Unicode and paste) for the next reader. The deadline also bounds sequence parsing. It does not disable theme querying or add sleeps. Screen disposal restores temporary tty mode even on errors and preserves terminal cleanup.

Shutdown PTY coverage verifies exact tty settings restoration, bracketed paste off, all mouse modes off, cursor visible, alternate screen off, appearance subscription off, no outstanding reply bytes, and bounded exit when the terminal never answers. Direct tests verify preserved genuine input and stopping at DA without consuming following input. All TerminalInput Read/TryRead call sites were reviewed; Program.cs is unchanged.

Manual check: `dotnet run --project src/PiSharp.Cli --no-build --no-restore` in a Linux PTY stayed interactive after the first OSC and remaining palette/DA responses, printed `/session` statistics, and exited with code 0 on `/quit`. The automated native PTY residual-input assertion verifies no parent-shell response chatter in the normal and immediate-exit reproductions.
