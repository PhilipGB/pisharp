PiSharp implementation (this branch):

- Vendors `grok-mermaid@0.2.3` `dist/*.js` under `src/PiSharp.Cli/Tui/Rendering/Mermaid/` with its Apache-2.0 `LICENSE.grok-mermaid` and a small `mermaid-render.mjs` host that reads Mermaid source from stdin and prints `render()` JSON. `PiSharp.Cli.csproj` copies `Mermaid/mermaid-render.mjs`, `Mermaid/dist/*.js` and the license to output. This is the deliberate hosting boundary; a pure C# layout engine remains future work.
- `TerminalMermaidEngine` spawns `node` for uncached sources (64 KB cap, 10 s timeout, concurrent cache), returns `null` for blank/unsupported/too-large/no-node so callers fall back to source fences. `TerminalMermaidRenderer` mirrors Pi: `IsMermaidInfo` (first info word case-insensitive), `ShouldAttemptRender` (`off`/thinking/`final`+streaming gates), width check, final-only condensed warning `Mermaid diagram not rendered: … (+N more)`, and `ThemedLines` mapping `border→borderMuted`, `text→text`, `edge→accent`, `edgeLabel→muted`, `title→accent+bold`, `none→plain`.
- `TerminalMarkdownRenderer` accepts `mermaidMode`/`isStreaming`/`isThinking`, only attempts top-level `FencedCodeBlock` whose parent is `MarkdownDocument` and whose info is Mermaid, returns themed diagram lines on success, otherwise renders the normal code block plus a `warning`-styled condensed warning for the final-invalid case. Lists, quotes and nested containers recurse but never render nested fences as diagrams. `RenderStreaming` passes `isStreaming:true`.
- `UserSettings` adds `MarkdownMermaid` with `DefaultMarkdownMermaid="streaming"` and `EffectiveMarkdownMermaid` (`off`/`final` else `streaming`, so `sometimes` falls back like Pi). `markdown.mermaid` parses as string alongside `codeBlockIndent`; project overrides user; unknown/duplicate/non-string `markdown` entries still throw. `UserSettingsWriter` allows `off`/`final`/`streaming`/clear. `TerminalSettingsPicker` inserts `markdown.mermaid` after `hideThinkingBlock` per Pi order with `off`/`final`/`streaming (default)` choices. `TerminalSettingsCommands`, `TerminalScreen.SetMermaidRenderingMode`, `TerminalConversationPresentation.SetMermaidMode`, `TerminalPresentation`, `InteractiveMode.RefreshProjectUi` and `RpcModeComposition.Adopt` re-render committed and live Markdown on change and on trusted-project reload.
- Thinking blocks never reach Markdown: `TerminalConversationPresentation.RenderThinking` renders plain `thinkingText`; the renderer also gates `isThinking`.

Limitations:

- Requires Node.js 22.19+ at runtime for diagrams; without Node all Mermaid fences fall back to source code blocks (no warning). No persistent Node process; each uncached source spawns once and is cached (≤1024 entries).
- Fallback code blocks retain PiSharp's existing code-block border/gutter and `markdown.codeBlockIndent` prefix; Pi has no gutter. Diagram lines themselves have no extra indent in either implementation.
- Warning line uses PiSharp `warning` token directly rather than Pi's `warning`-inside-`mdCode` code span; stripped text matches Pi (`Mermaid diagram not rendered: …`), ANSI differs by theme.
- Only `flowchart`/`graph`, `stateDiagram`, `classDiagram`, `erDiagram`, `sequenceDiagram` render via the vendored library; other Mermaid types fall back like Pi's `render()==null`.
