PiSharp implementation (this branch):

- Vendors `grok-mermaid@0.2.3` `dist/*.js` under `src/PiSharp.Cli/Tui/Rendering/Mermaid/` with its Apache-2.0 `LICENSE.grok-mermaid`, a one-shot `mermaid-render.mjs` host and a persistent `mermaid-worker.mjs` line-delimited JSON worker (`{"id","source"}` → `{"id","art"}`). `PiSharp.Cli.csproj` copies `Mermaid/*.mjs`, `Mermaid/dist/*.js` and the license to output. README documents the Node 22.19+ requirement; without Node all fences fall back (no warning, no crash). This is the deliberate hosting boundary; a pure C# layout engine remains future work.
- `TerminalMermaidEngine` keeps the synchronous one-shot path for direct renderer unit tests (64 KB cap, 10 s timeout, concurrent cache, `null` for blank/unsupported/too-large/no-node). `TryGetCached`/`CacheForTests` expose the cache without spawning. `TerminalMermaidWorker` is the persistent worker: single `node` process, serialized requests, `ProcessCreationCount` for bounded-process verification, restart on crash/EOF. `TerminalMermaidRenderer` mirrors Pi: `IsMermaidInfo`, `ShouldAttemptRender`, width check, final-only condensed warning, `ThemedLines` mapping, plus `CollectEligibleSources` (top-level fences only).
- Responsiveness (P1): `TerminalMarkdownRenderer` accepts an injectable `mermaidRender` func. `TerminalConversationPresentation` uses the cache-only sync provider under the screen lock (fast, never spawns), then debounced (20 ms) coalesced async upgrades outside the lock via `_mermaidAsyncProvider` (default `TerminalMermaidWorker.RenderAsync`) with monotonic `_mermaidVersion`. `EnqueueMermaidUpgrades` cancels the previous debounce, skips cached/ShouldAttempt-false, and after the worker returns caches and calls `ApplyMermaidUpgrade` only if the version still matches; `ApplyMermaidUpgrade` re-renders via the cache-only path under `_applyUnderLockAndRequest` (Screen holds `_gate` briefly, no external wait) and requests a frame. Obsolete results are discarded by version, subprocess creation is bounded to the persistent worker (1 process). `TerminalScreen` passes the locking apply callback and injectable providers for tests.
- `TerminalMarkdownRenderer` only attempts top-level `FencedCodeBlock`, returns themed lines on success, otherwise code block plus `warning`-styled condensed warning for final-invalid. Lists/quotes/nested never render nested fences. `RenderStreaming` passes `isStreaming:true`.
- `UserSettings` adds `MarkdownMermaid` with `DefaultMarkdownMermaid="streaming"` and `EffectiveMarkdownMermaid` (`off`/`final` else `streaming`). Project overrides user; unknown/duplicate/non-string `markdown` still throws. `UserSettingsWriter` allows `off`/`final`/`streaming`/clear. Picker inserts after `hideThinkingBlock`. Commands/Screen/Presentation/InteractiveMode/RpcModeComposition re-render on change and reload.
- Thinking blocks never reach Markdown; renderer also gates `isThinking`.

Benchmark (local, same machine):
- Persistent worker: 20 renders in ~0.055 s, 1 process.
- One-shot spawn per render: 20 renders in ~0.939 s, 20 processes.
- 100 incremental live updates via the coordinator complete with a single worker process and only the latest upgrade applied (see `TerminalMermaidAsyncTests`).

Verification (source-pinned, deterministic, no live models):

Limitations:

- Requires Node.js 22.19+ at runtime (README); without Node all fences fall back (covered by `NoNodeFallbackRendersCodeBlock`). Persistent worker is 1 process; each uncached source is cached (≤1024 entries).
- Fallback code blocks retain PiSharp gutter/indent; Pi has none. Warning uses `warning` token directly; stripped text matches Pi.
- Only library-supported types render; others fall back like Pi.
