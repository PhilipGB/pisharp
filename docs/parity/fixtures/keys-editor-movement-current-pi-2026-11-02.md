## Corrections

The existing editor already had grapheme movement, logical-line Home/End, word
movement and a basic history list. The audit confirmed these defects:

- Vertical movement used logical lines. Pi moves by visual row, including
  soft-wrapped rows, with its sticky preferred-visual-column decision table.
  `EditorVisualLines` now implements Pi's word-aware wrapping (whitespace and
  CJK break opportunities), and `EditorBuffer` uses it for Up/Down, page
  movement and selection extension.
- Character jump mode was absent. `Ctrl+]` and `Ctrl+Alt+]` now wait for the
  next character, are case-sensitive, exclude the cursor cell, cross logical
  lines, cancel on the same shortcut, and fall through on control input.
  Printable jump targets previously bypassed `EditorBuffer.Handle` through
  `InsertText`; terminal input now routes them through jump mode.
- Page movement was absent. `tui.editor.pageUp/pageDown` now use Pi's
  `max(5, floor(terminalRows * 0.3))` formula. Fullscreen PageUp/PageDown keeps
  transcript ownership; Ctrl+PageUp/Down reaches the editor.
- Soft wrapping was character-based. `EditorViewport` now renders Pi-compatible
  word-aware rows, tracks a persistent editor scroll offset, and normalizes tabs
  to four spaces like Pi's `setText`/`insertText`.
- Ctrl+F was bound to transcript search on non-Windows terminals, stealing
  Pi's `tui.editor.cursorRight`. The non-Windows search default is now
  `Ctrl+Shift+F` only.
- Legacy F1-F12 sequences were not decoded. `TerminalInput` now decodes
  `ESC[11~` through `ESC[24~`, modified F-keys with explicit noncontiguous
  xterm codes (including F6 at `ESC[17;5~`), and their Kitty equivalents.
- Buffered printable input after jump activation could be consumed as one
  literal search string. Pinned Pi treats the first buffered grapheme as the
  jump target and types the remainder; `EditorBuffer.HandleJumpText` now does
  the same and has a real PTY regression (`aXY,b,c`).

## Findings

- **CJK word segmentation (non-required).** Pinned Pi delegates word boundaries
  to `Intl.Segmenter` (ICU). For a contiguous Han run, Pi breaks at dictionary
  boundaries while `EditorBuffer` treats the run as one word. The required
  matrix covers grapheme, combining, emoji and multiline boundaries; reproducing
  ICU dictionary segmentation needs an ICU dependency or embedded dictionary.
- **Keyboard selection extension (non-required).** Pinned Pi has no keyboard
  selection-extension actions; its selection is screen-level mouse text
  selection. PiSharp retains Shift+arrow selection. N14 verifies Pi-supported
  selection effects (ordinary movement collapses selection, submission sends
  the complete draft, mouse selection does not move the cursor) and records the
  extension explicitly.
- **Terminal rendering/control differences (non-required).** See the paired
  difference records. They do not change editor text, cursor lifecycle,
  terminal restoration or provider input.
