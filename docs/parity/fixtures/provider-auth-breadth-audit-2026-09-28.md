Since provider audit pin `cd5ff1125981f0fc37a56df25eee7310286a3f89`, current `main` adds durable/package work only; `packages/ai` and `packages/coding-agent` provider source is unchanged. ## Current Pi surface

`packages/ai/src/types.ts` declares 10 chat API families and 42 built-in provider IDs. The API families are `openai-completions`, `mistral-conversations`, `openai-responses`, `azure-openai-responses`, `openai-codex-responses`, `anthropic-messages`, `bedrock-converse-stream`, `google-generative-ai`, `google-vertex`, and `pi-messages`. Provider profiles also register image and classifier APIs separately; OpenRouter has an `openrouter-images` adapter and TypeSafe classifier support.

Eight built-in providers expose OAuth methods: Anthropic, GitHub Copilot, Kimi Coding, Meta, OpenAI Codex, OpenRouter, Radius, and xAI. `packages/ai/src/auth/resolve.ts` gives a stored provider credential ownership over ambient credentials. API-key profiles resolve stored keys before environment/config values. OAuth profiles refresh tokens inside the serialized credential-store mutation, normally before five minutes of remaining lifetime, then derive provider request auth. Login methods own browser/device/manual-code interaction, and some OAuth providers change model availability or request headers.

Pi's provider-specific integrations are material. Examples in current source include Codex Responses with subscription OAuth, Google GenAI and Vertex authentication, AWS Bedrock credential resolution, Mistral reasoning and tool-call conversion, and GitHub Copilot's three API paths. Current upstream commits `dc84c1ac0afd15721071507a3a06b5e3d0cad614` and `c1449660c83fd00a7c71d5f7e1bd29fafd400550` change Mistral effort mapping and OpenCode/Qwen empty thinking-signature replay respectively. Current generated Pi metadata includes 33 Mistral chat models.

## PiSharp current boundary

`BuiltinProviderProfiles` defines OpenAI, Azure OpenAI Responses, OpenRouter, Mistral, Anthropic, xAI, OpenAI Codex, and Google GenAI, plus optional local/custom endpoints. PiSharp supports seven API identifiers across six protocol families: `openai-responses`, `azure-openai-responses`, `openai-completions`, `anthropic-messages`, `mistral-conversations`, `openai-codex-responses`, and `google-generative-ai`. Google GenAI uses a dedicated REST/SSE boundary with `x-goog-api-key`, generation/thinking configuration, function-call/result conversion, model-scoped thought-signature replay and Gemini-version image routing. Its embedded snapshot carries 22 current-Pi models. Google and provider-factory tests pass 33/33 locally; no exact-head CI or upstream Google differential has run. Azure OpenAI uses the Responses SDK with Azure `api-key` authentication, configurable API-version/deployment mapping, per-session prompt cache keys, and a 43-model current-Pi snapshot; exact-head Linux CI run [36452261244](https://github.com/PhilipGB/pisharp/actions/runs/36452261244) passed 764/764 tests, but provider-wide image/tool/usage/error behavior is not verified. Mistral uses `/v1/chat/completions`; its explicit adapter retains the MAF/OpenAI client loop while mapping Mistral `reasoning_effort`/`prompt_mode` and normalizing historical tool-call IDs to nine alphanumeric characters with correlated tool results. Its checked-in catalog carries all 33 current-Pi model records, including reasoning maps, image modalities/resize limits, context/output limits and pricing; listing is static. Codex uses the Responses SDK over its account-scoped SSE endpoint, supplies session affinity, and carries current-Pi static model metadata. Exact-head Linux CI run [36462567719](https://github.com/PhilipGB/pisharp/actions/runs/36462567719) passed format, warnings-as-errors build and 779/779 tests (0 skipped). Codex WebSocket/cached transport and broader image/tool/usage/error behavior remain unverified.

`ProviderModelRuntime` resolves API-key credentials from a runtime `--api-key` override, stored user `auth.json` key, configured `models.json` key, then provider environment key. `AuthStorage` is private and atomic on Linux. OpenAI Codex is now the first active OAuth provider: browser PKCE and device-code login persist credentials; expired tokens refresh under serialized storage mutation; the ChatGPT account claim supplies request authentication; Codex rejects API-key credentials and does not fall back to ambient API keys. Tests cover restart persistence, concurrent refresh, cancellation, invalid/expired credentials, dynamic request headers and offline status; exact-head CI run `36462567719` passed 779/779. Manual-code paste fallback and the other seven built-in OAuth providers remain open. There is no project credential scope.

Most online catalog discovery uses a generic OpenAI-compatible `/models` request. Anthropic, xAI, Mistral, and Azure OpenAI use local profile catalogs. PiSharp supports image input in existing adapters, but this provider audit does not verify image, cache, usage, or error-wire equivalence across providers. Mistral session affinity and `prompt_cache_key` behavior remain open.

## OpenCode/Qwen empty-signature replay

Pi `11894012dd461232eb075bc890538b6866860a10` marks OpenCode and OpenCode Go `qwen3.8-flash` with `compat.allowEmptySignature`; its Anthropic adapter otherwise converts unsigned thinking history to text. The two current upstream suites pass 98/98.
