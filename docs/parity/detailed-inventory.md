## RPC and JSON events (`rpc-commands.md`, `json.md`, `src/modes/rpc/`)

The commands below are reference interfaces, not claims of implementation; the feature matrix and notes identify partial subsets, and no RPC group is Verified. JSONL uses literal LF framing (not JavaScript `readline`'s Unicode line separators); stdout must contain only protocol records. PiSharp `prompt` replies after preflight with `started` or `queued`; failures return one correlated error. An active-run `prompt` requires `streamingBehavior` set to `steer` or `followUp`; direct `steer`/`follow_up` success responses also include `data.disposition: "queued"`. Success means accepted, not completed; `agent_settled` follows retries/queued work, unlike `agent_end`.

- Prompt/queue: `prompt`, `steer`, `follow_up`, `abort`, `clear_queue`, `new_session` (event-order and queue-cancel tests). RPC emits one top-level `agent_start`/`agent_end` pair per local run, `turn_start`/`turn_end` for model turns and payload-free `agent_settled` after retry/queue settlement. Process fixtures cover ordinary and tool turns; deterministic in-process tests cover queued turns, retry, error and cancellation ordering. A separate session retry policy reports `willRetry`, emits `auto_retry_start`/`auto_retry_end`, and supports `abort_retry`; provider-request retry is separate. Preflight rejection emits only its correlated response. Current-Pi retry/failure/cancellation differentials and broader run aggregation remain open.
- State/model: `get_state`, `get_messages`, `set_model`, `cycle_model`, `get_available_models`, `set_thinking_level`, `cycle_thinking_level`, `get_available_thinking_levels`, `set_steering_mode`, `set_follow_up_mode`. Model selection validates exact catalog IDs, rebuilds the shared runtime and records session model changes; cycling wraps and returns `null` for zero/one available choices. Thinking commands persist Pi `thinking_level_change` entries, restore the selected branch level and include it in `get_state`; model-specific thinking maps remain absent. `RpcModelCommandHandler` owns this family. Set/cycle thinking work during runs; changes apply at the next provider request and persist after the in-flight history write. Idle and active changes emit top-level `thinking_level_changed` before the response and suppress it when unchanged. `set_session_name` appends and persists a Pi `session_info` entry, then emits Pi-shaped `session_info_changed` before its response. Queue snapshots use top-level `queue_update`; `get_entries` and `get_tree` use Pi-shaped entry/tree projections. The `get_state` response, model-specific thinking maps and remaining event families stay open.
- Recovery/context: `compact`, `set_auto_compaction`, `set_auto_retry`, `abort_retry` (asynchronous failure and settled-event tests).
- Shell/stats/export: `bash`, `abort_bash`, `get_session_stats` (in progress: approximate context, persisted provider token/cost accounting including cache-write counts; no Pi wire format), `export_html` (in progress: private non-overwriting HTML, no Pi wire format). Direct `bash` and `abort_bash` use the same `CodingTools` runner, return structured result/error data, persist direct executions as separate `bash_execution` entries, stream request-correlated updates, and have service and real CLI RPC-process fixtures for nonzero exit, truncation and cancellation. Extensions admitted by the personal, project-trust, or explicit-path rules can register `user_bash` handlers for direct RPC requests; the first non-null result claims the command, handlers can stream correlated updates, and exceptions emit `extension_error` before trying later handlers or the shell. Direct Bash strips ANSI CSI/OSC and unsafe control characters, removes carriage returns, and replaces invalid UTF-8; interactive streamed Bash display uses the same filter while model-tool provider context stays raw. Model-invoked Bash receives current `PI_SESSION_ID`, optional `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, and `PI_REASONING_LEVEL`; stale inherited values are cleared first. `excludeFromContext` persists across restore and omits the synthetic result from provider messages; default results project into context and remain visible in HTML export. Updates remain inside the PiSharp JSON event wrapper. The Pi RPC extension wire contract, exact truncation/error details, terminal PTY presentation and wider pinned wire/result differentials remain open.
- Bash signal results: the pinned tool tests expect shell self-termination by `SIGKILL` and `SIGTERM` to preserve prior output and report exit codes 137 and 143. `CodingToolsTests.BashSignalTerminationUsesShellExitCodesAndPreservesPartialOutput` verifies those same results on Linux; Windows and wider signal/tree behavior remain unverified.
- Bash timeout and abort details: pinned `tools.test.ts` checks that timeout and abort errors retain truncation notices and a readable full-output log path. `CodingToolsTests.BashTimeoutRetainsFullTruncatedOutputAndReportsItsPath` verifies the timed-out case against 3000 lines; `AgentIntegrationTests.AbortedBashToolRetainsTruncationNoticeAndFullOutputPath` aborts a model-invoked Bash tool after 3000 lines, then verifies the finished tool error retains the tail notice and its complete readable log while the agent run settles.
- Tree/session: `switch_session`, `fork`, `clone`, `get_fork_messages`, `get_entries`, `get_tree`, `get_last_assistant_text`, `set_session_name`, `get_commands`. Session replacements cancel an active run and rebind to the stored project CWD. Fork/clone/switch and set-name persistence have process fixtures. `get_entries` shares Pi JSONL entry projection, supports the Pi `since` cursor and omits the format marker. `get_tree` returns nested Pi-shaped nodes with labels and timestamps. Broader session-manager/recovery differentials and remaining session command/event shapes are open.
- Events: `agent_start/end/settled`, `turn_start/end`, `message_start/update/end`, `tool_execution_start/update/end`, `queue_update`, `entry_appended`, `session_info_changed`, `thinking_level_changed`, compaction and retry. Pi-shaped run, turn, message, tool, queue, thinking-level and session-name projections have process or deterministic tests, including consumed steering messages, error/cancellation snapshots, and equality across message_end, turn_end and agent_end. Retry context omission appends and saves each `context_edit` before projecting Pi-shaped `entry_appended`; a CLI process test verifies the entries arrive before retry continuation, and provider-turn reconciliation retains completed assistant/tool history after MAF continuation failure without duplicating tool results with changed timestamps. Extension boundary appends, compaction events, process-level error/cancellation differentials and broad current-Pi comparisons remain open. Microsoft.Extensions.AI 10.10.0 aggregates OpenAI tool argument fragments into a completed `FunctionCallContent`, so that adapter produces one complete JSON `toolcall_delta` rather than raw argument fragments.
